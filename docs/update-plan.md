# Plan: update features 1–5

This is the reviewed implementation plan, retained for context. Current behavior, verification results, and unsupported operations are documented in [API contract evidence](api-contracts.md) and the [README](../README.md).

1. Establish current state and inspect Skippo's public app for concrete writable contracts. Maintain a matrix of field, endpoint, payload, clearing semantics, evidence, and live verification. No invented backend fields or endpoints; distinguish app-source evidence from live behavior.
2. Implement `events update ID`: partial explicit changes to title, description, date, category and supported cost/currency/source; reuse ID, preserve other writable values and check attachment IDs after write. No retries on uncertain writes; preserve existing reconcile guidance. Test fuel/non-fuel categories and zero, duplicate names, missing IDs, concurrent changes and `--dry-run`.
3. Add explicit clears to optional insurance expiry, settings, fuel quantity/cost and engine fields only where exact server semantics (omission vs null vs empty) are established, verified by isolated temp-boat live reads. Distinguish 0, empty string and missing. Reject update+clear conflicts; preserve unspecified fields; verify cleared fields actually absent. If unable to establish safe clearing, document the specific limitation rather than fake success.
4. Research checklist item edit/list rename/reorder/create. Implement only operations supported by source and validated by the service; no deletion/recreation that silently changes ID or status. If unavailable, document as unsupported with evidence.
5. Research boat brand/model and engine brand/model/serial, named home harbor, multiple engines. Add only verified fields with exact ID/model selection and readback. Preserve unmodified fields. Remove nonfunctional `--number-of-engines` from help; for backwards compatibility, keep parsing it with a clear error until explicitly removed in a later version. Never write catalog dimensions. Don't assume a single engine when multiple returned.
6. Add `config unset boat` under existing lock/atomic update, preserve other local settings, idempotent without remote request.
7. E2E: baseline suite first. Extend real-HTTP subprocess tests against installed wheel for create/update/readback, omitted/empty/zero/clear, absent/foreign IDs, untouched fields, attachments, dry-run zero writes, noninteractive input, server errors and uncertain write semantics. Do not claim optimistic locking unless supported by server; read-before-write is not atomic. Verify actual flags/help, no output of secrets or signed URLs.
8. Live test using supplied 1Password link in memory only. Never print or persist link, password, tokens, personal data, or signed URLs. Read-only current account, then use only uniquely named TEMPORARY boat and its synthetic events/checklists/attachments; register cleanup immediately and verify exact temp ID absent after tests; preserve existing user's boats. Any cleanup failure blocks completion and is reported. Source-derived temporary boat setup/delete may use private test harness; do not extend production allowlist solely for fixtures. No blind retry after uncertain writes.
9. Run full tests, lint, wheel/sdist build, installed-wheel E2E Python 3.10 and 3.14 where available, secret scan current tree/artifacts, update README and API matrix with exact live vs simulator coverage and unsupported fields. Commit reviewed files, push main, watch GitHub CI and fix failures. User explicitly authorized commit/push. Public repo history contains intentionally public client config from Skippo: never add actual provider keys or account credentials.
